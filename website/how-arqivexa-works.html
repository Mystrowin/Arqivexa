Arqivexa / How it works

Explorer-first workflow

How Arqivexa works without extracting the whole archive first.

Arqivexa presents a .cfs archive as a folder-like workspace in Windows 11 File Explorer. With ProjFS available, directory information is projected and file contents are supplied on demand.

01

Open

Start from one compressed archive.

Create a new archive

Use the supported Explorer creation workflow to create an empty archive or compress supported files from a folder into one .cfs file.

Open an existing archive

Double-clicking a supported archive starts the Arqivexa command/broker workflow and prepares its managed workspace.

One writable session

Repeated opens reuse the managed writable session rather than intentionally creating competing writers for the same archive.

02

Project and hydrate

Explorer sees files before every byte is decompressed.

Projected directory structure

Windows Projected File System lets Arqivexa expose the archive's directory tree through Explorer.

On-demand file data

When an application opens a projected file, Arqivexa supplies that file's compressed content as needed instead of performing a complete up-front extraction of the archive.

Application access can hydrate files

Preview handlers, antivirus, indexing, memory mapping, and normal applications can request file data and trigger hydration.

03

What ProjFS provides

Projection and hydration are building blocks.

Enumerate the directory

Arqivexa reads archive metadata and presents directory entries to the projected workspace. Placeholder entries let Explorer show files without first writing every complete payload into an extracted directory.

Supply data when requested

When a process reads a file, Arqivexa retrieves and decompresses the needed data through the ProjFS provider path. Files that are never requested do not need to be hydrated just because the directory was browsed.

Arqivexa provides the archive logic

ProjFS does not turn arbitrary archive formats into editable filesystems by itself. Arqivexa supplies the format, decompression, metadata mapping, change tracking, validated persistence, and recovery lifecycle around Windows' projection primitives.

It is a ProjFS-backed workspace, not a block-device virtual disk or a general driver for mounting arbitrary archive formats.

04

Edit and persist

Supported workspace changes can be saved back.

Edit through normal Windows applications

Supported operations include creating and changing files within the mounted workspace. Arqivexa tracks the session rather than requiring a separate permanent extracted copy.

Automatic persistence

Ordinary mounted edits are committed after a quiet period. Explicit close, discard, commit, and recovery paths remain distinct.

Transactional replacement

Arqivexa validates a candidate archive before promotion and retains a validated predecessor across the transaction boundary so a failed save does not silently replace a readable archive. It also checks archive identity to avoid silently overwriting a file changed outside the managed session.

After closing the workspace, the Optimize operation can remove obsolete archive history.

Applications can use memory mapping, file locks, temporary save files, atomic replacement, preview handlers, or indexing. Their access patterns can affect compatibility, so test unfamiliar software with a copy and keep an independent backup.

05

Archive format

What is stored in a .cfs file?

The extension is retained

.cfs comes from the product's former CFS name. The product is Arqivexa; the extension remains for compatibility with existing archives and integrations.

Independent LZMA2 compression

Each file is compressed separately rather than sharing one solid compression stream across the archive. That supports file-oriented access, though solid compression can produce smaller archives for some collections of similar files.

Large files use checked chunks

The current CFS2 format stores file data in chunks up to 64 MiB and records metadata needed to rebuild the projected directory.

Editing can add archive history

Changed data can be appended while obsolete versions remain in the archive. After closing the workspace, Optimize can rewrite and validate a compact archive.

LZMA2 does not define the file format

A .cfs archive is not interchangeable with a 7z archive or any other file just because it also uses LZMA2.

Compression is not encryption

Arqivexa 0.6.0 compresses archive contents but does not encrypt them. Keep independent backups of important files.
